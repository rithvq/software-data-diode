## Implemented scope

`shared/coverage/models.py` defines frozen Pydantic models with immutable nested tuples: RuleContract, AtomicCondition, WindowIdentity, ConditionFacts, RuleVerdict and supporting device/metric/expression/trace types. The contract declares accepted normalized gateway ingress, finite binary64, metric paths/units, minimum samples, UTC alignment and bounded cardinalities. Hard ceilings are 16 devices, 64 conditions, 32 rules, 16 registered metrics/device, eight expression levels and 127 nodes/rule; contracts can declare smaller limits.

EXISTS uses K=1. COUNT_GE counts observations satisfying a numeric inequality, not the sum of a measurement. Only >, >=, <, <= and same-window bounded AND/OR expressions are accepted. Arbitrary expressions, NOT, unregistered references, repeated leaf references, ambiguous identifiers, unknown fields, bad units, nonfinite thresholds, boolean/string thresholds and invalid counts fail validation.

`contracts.py` provisions local files through strict duplicate-key JSON parsing and a 64 KiB input ceiling. Hashing reuses the existing canonical JSON helper over the entire resolved validated document, including defaults, semantic metadata, units, device registrations, limits and expression structure. Array order is retained and keys are sorted. Signed zero thresholds normalize to positive zero. Parsed inequalities compare binary64 directly, without rounding or tolerance.

Golden synthetic contract:

```text
SHA-256: 5ac9d246d40fc6a333c68fe984025d7f6169bec2fe3e85589c5af3cee51204bd
Canonical length: 3835 bytes
Profile: rccd-contract-v1
```

Use `parse_contract`/`load_contract` as the JSON entry points; ordinary Pydantic JSON parsing is not the duplicate-key boundary. Explicit model-construction bypass APIs are not supported provisioning paths.

`evaluation.py` partitions original observations into matching/nonmatching/unresolved counts. Missing metrics and wrong telemetry types remain in the device population as unresolved. It uses lower/upper count bounds, rejects mixed hashes/epochs/windows/devices and overlapping fact scopes, and applies strong Kleene composition. Positive witnesses may answer TRUE before closure; incomplete/empty/undersampled scopes cannot justify FALSE. Clock-discontinuous scopes cannot justify either definite answer. A FALSE AND-rule may use one negative condition while another remains UNKNOWN; the result retains unknown conditions, minimal supporting conditions and incomplete coverage. Artifact verification remains NOT_PERFORMED and device health NOT_ASSESSED.

## Time lifecycle

`windows.py` provides injected UTC/monotonic clocks and integer-microsecond half-open windows aligned to Unix epoch. Offset-aware timestamps normalize to UTC without floating timestamp arithmetic. The exact upper boundary belongs to the next window.

Startup inside a window marks STARTUP_PARTIAL. Monotonic deadlines schedule closure; normal delayed polling does not invalidate every successor window. Skipped windows are reported as a count, never invented as complete empty scopes. Interruption seals a limited scope. A UTC/monotonic disagreement, backward monotonic clock or unsafe boundary disagreement halts that schedule and emits CLOCK_DISCONTINUITY. It cannot reopen a sealed index.

The declared default jump tolerance is 100,000 microseconds; even a smaller boundary disagreement halts conservatively if membership and deadline cannot agree. Pass the contract's tolerance to WindowSchedule. Scheduling must run under the future serialized admission writer. This is not durable restart reconciliation, hardware time synchronization or a continuous-time predicate implementation. N2 must reconcile epochs/open windows before admitting new records.
