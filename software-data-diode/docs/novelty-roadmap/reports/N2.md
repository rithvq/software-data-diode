## Implementation and boundaries

Added `shared/coverage/ledger.py` with immutable limits/receipts and a SQLite ObservationLedger. The fixed device registry comes from the N1 contract. Outgoing UUIDs, signing, transport sequences and `shared/edge/state.py` remain separate and unchanged.

One OS-held writer lock prevents a second cooperating process from opening the store; an RLock serializes transactions across threads. SQLite uses BEGIN IMMEDIATE, rollback-journal DELETE mode, synchronous FULL and foreign keys. Canonical normalized input, original identity, ingress window, partitioned condition counts, PENDING_POLICY disposition, retry high-water mark and an UNSIZED evidence obligation commit together. A receipt is returned only after COMMIT succeeds.

The identity is `(ledger_epoch, device_id, ingress_sequence)`. Original ingress counters are per device, persistent and never reset by ordinary restart, compaction or controlled epoch retirement. The canonical input binds the whole validated original message, not a filtered payload. Missing relevant metrics and unexpected telemetry types contribute unresolved evidence; unregistered devices and malformed/refused inputs do not enter the accepted scope.

UNSIZED/reserved_bytes=0 means the future evidence cost is not sized or reserved yet. N2 stores that obligation state but performs no irreversible reduction, signs no capsules and makes no evidence-service guarantee. The retained input rows also form the bounded pending policy outbox; no signed transport outbox is claimed.

Admissions run through `asyncio.to_thread`; at most eight storage admission tasks can be outstanding. Full slots refuse new work with 429. Disconnect/cancellation does not release a slot while its underlying write is unfinished. Shutdown awaits outstanding admissions and closes the store. The clock worker shares the writer lock. Storage/clock failure makes readiness fail visibly.

## Retry and epoch contract

Research ingress requires `X-Coverage-Epoch` and `X-Coverage-Retry-Sequence`. The latter is a positive, strictly increasing per-device local request sequence, retained by the caller across retries/restarts. It is not the gateway ingress counter or outgoing transport sequence.

An identical retained retry returns the original receipt, even after restart or expiry of its original source timestamp. A changed canonical input under the same retry key conflicts. A lower/compacted retry is refused using persistent high-water marks, not admitted as a new sample. Concurrent independent devices are supported; clients must serialize their own increasing request sequence. An out-of-order lower request that was never accepted is refused, not silently counted.

Provisioning is explicit through `shared.coverage.runtime_state`; ordinary gateway startup never creates missing state. A small fsynced identity anchor binds the store ID and research project. Missing/corrupt/mismatched state is refused, and an existing anchor prevents re-provisioning a missing database with a fresh UUID. The contract hash is pinned to the store; silent contract switching is refused.

Controlled `retire_epoch` requires the expected current epoch, a checkpoint digest and a quiescent store after verified local archival/compaction. It records a chained retirement head/generation and creates a new epoch, but preserves ingress/retry counters and closed-window floors. All noncurrent epochs are refused. This is not a Fog epoch-provisioning or receiver replay implementation. N6 must establish its own trusted epoch acceptance rules.

## Window and recovery semantics

Membership is integer gateway UTC captured under the serialized admission writer, before the insert/commit, with N1's aligned half-open 10-second windows. Commit can finish later; closure cannot interleave with a partial transaction. Source timestamps are provenance/freshness inputs only.

Startup recovers before accepting requests: SQLite integrity/identity/contract checks, bounded cardinality checks, counter checks, canonical-input hashes, window membership, dispositions/obligations, fact partitions and recomputation of facts from retained original records. Open scopes are closed with INTERRUPTED limitations; counters and unsized obligations remain. No missing historical windows are synthesized. The same closed window cannot be reopened, even by a device that did not previously submit in it. A restart within a sealed window may delay new admissions until the next boundary; readiness exposes that block.

The injected UTC/monotonic scheduler is copied for each candidate transaction and adopted only after commit. A rolled-back admission cannot leave the in-memory clock ahead of persisted closure. Clock jumps seal observed scopes with CLOCK_DISCONTINUITY, persist a closed-window floor/limitation and refuse the new admission. That scheduler halts; reopen/reconcile with trustworthy later time is required. Moving the wall clock backward or rotating the epoch cannot bypass the retained floor.

## Bounds and compaction

Default bounds, validated by LedgerLimits:

| Material | Limit |
|---|---|
| Canonical normalized input | 8,192 bytes/observation |
| Device state | N1 registry, at most 16 devices; fixed counter/chain rows |
| Active observed scopes | 16 device/windows |
| Retained observed scopes | 256 device/windows |
| Retained original records | 10,000 |
| Pending policy outbox | 16 MiB canonical input bytes |
| Main SQLite file | 32 MiB; 4,096-byte pages and max_page_count |

Limits may be lowered through the library but invalid/out-of-range configurations fail. The gateway currently uses these defaults; additional deployment tuning is not wired in N2. Database/index/metadata overhead is covered by the page cap, not miscounted as payload bytes. Nonstandard page sizes are refused. DELETE journals are transient and can require roughly another database-sized allocation plus SQLite headers; the main-file limit is **not a whole-volume quota**. Budget additional disk headroom. Disk I/O/full errors refuse acknowledgment and require reopening; a finite store does not promise indefinite availability under overload.

Nothing is automatically evicted to obtain space. Compaction requires a closed scope and a canonical, fsynced raw-input/fact archive exported to a new file **outside the ledger directory**. Existing archive files are never overwritten. Retirement compares that archive with the closed scope; compaction and recovery recheck its digest/existence. Missing or changed archival evidence blocks deletion. The chained retirement head, device high-water marks and closed-window floor survive compaction. Archived original inputs/facts remain the durable retired scope for offline inspection, not signed Fog evidence.

Local archival retirement is an explicit administrative operation, not confirmed Fog delivery. External archive retention/capacity is separately managed by the operator; it is not silently accumulated on the Edge ledger volume. Do not delete required archives between retirement and compaction. Host-administrator deletion/rollback of all state, filesystem attacks and dishonest storage/clock hardware are outside this software durability guarantee. A local digest is not an externally trusted anti-rollback anchor.
