## Implemented

- FogEvidenceVerifier reuses canonical N3 serialization, SHA-256 and Ed25519.
  It checks version/kind, signer/public-key provisioning, immutable scope, active
  epoch/contract, aligned window, accepted ranges/count partitions, condition set,
  hash-pinned metric units, bounds, all unique signed parts and receipt-time freshness.
- Immutable VerificationRecord includes scope, digest, verifier version, assurance,
  continuity, limitations, reasons, original receipt time and completed-part costs.
  Assurance is AUTHENTICATED_SUMMARY: hidden originals are not independently recomputed.
- FogEvidenceStore extends the existing private, anchored N5 SQLite spool. Accepted
  signed variants commit durably before being counted as spooled. Valid forks are
  retained for PostgreSQL quarantine instead of being discarded by the N5 duplicate
  constraint. Raw/state replay behavior and legacy HTTP security are unchanged.
- PostgreSQL atomically commits epoch binding, durable window highwater, scope,
  signed body/parts, facts, verification outcome, timing and publication identity.
  Exact duplicates create no second capsule/publication/performance row.
- Valid same-scope forks quarantine both bodies and remove their facts from the
  usable view. Existing affected verdict rows become UNKNOWN/CONFLICT; a new
  publication revision requests downstream reassessment. Invalid unrelated input
  only produces a separate outcome and cannot overwrite accepted evidence.
- Missing predecessors produce GAP continuity. Later independent facts remain valid.
  Predecessor arrival/conflict reassesses directly affected continuity and publication
  revisions. ROOT is a declared chain root, not global observation completeness.
- A transaction-scoped publication consumer locks the revision and commits consumer
  effects with completion. Failure rolls back both; repeated consumption is a no-op.
  No N7 rule execution or real rule alert producer was added.
- Blocking crypto/SQLite/PostgreSQL calls run off the event loop. Shutdown waits for
  uncancellable storage tasks before closing the writer. Readiness is local bounded
  intake availability, not PostgreSQL delivery or a signal sent back to Edge.

## Storage and Recovery Contract

Defaults retain the N5 16 MiB SQLite page cap, an 8 MiB logical spool budget, at most
1,024 raw/state/evidence records, 256 queued frames, 32 partial assemblies / 1 MiB,
five-second assembly expiry and 1,200-byte datagrams. Outcomes have a separate
maximum of min(128, record_limit/4), with 2,048-byte metadata. Evidence and outcome
publication alternate when both are pending. Impossible maximum-artifact spool
budgets fail before creating new state. Overflow/storage errors are visible; no
artifact is counted as durably spooled when its transaction fails.

Evidence bytes, parts and original successful Fog receipt time survive restart.
PG failure leaves work pending. A crash after PG commit but before spool completion
retries idempotently. Publication after a long outage uses the original committed
receipt's freshness assessment; it does not pretend the signed artifact arrived anew.
A newly arriving expired artifact is rejected. Durable epoch retirement and window
watermarks do not expire with the SQLite body cache. PG identities/watermarks have
no automatic expiry; manual deletion or pruning is not a supported replay reset.

Retained N5 evidence is imported without deleting its original rows. Because N5 did
not retain receipt timestamps or signed transport parts, these records are explicitly
LIMITED / LEGACY_RETAINED_BODY / HISTORICAL_N5_RECEIPT_TIME_UNAVAILABLE. No historical
freshness or complete-part verification is fabricated. Partial assemblies are bounded
in memory, not recoverable across restart: an incomplete assembly is never accepted
as evidence. Complete parts are stored in PG; expiry outcomes record partial counts.

Only the existing pinned key/epoch/contract is active. Unknown keys/hashes/epochs,
changed anchors and received transition activation are refused. Even a signed
transition between provisioned hashes requires explicit local operator migration;
hot key/contract/epoch handover is not implemented. N5's positive research sequence
constraint is retained for live window indices. Pure N1/N3 historical vectors are unchanged.
