## Implemented Semantics

shared/coverage/rules.py delegates rule truth to the N1 evaluator. It adapts only
hash/epoch/device/window-matched verified RCC assertions and checked original
disclosures into ConditionFacts. It does not query accepted_telemetry or pass
summary means to raw-sample detectors as an exact-preservation method.

EXISTS and COUNT_GE use matching lower bounds and complete-scope matching plus
unresolved upper bounds. Positive facts can justify TRUE with incomplete coverage.
FALSE requires the N1 closed/population/sample/count conditions. Missing, retired,
conflicting or unsupported scopes do not supply negative facts. Clock-discontinuous
facts cannot justify either definite answer. No-input scopes remain undersampled,
not no-event certificates. AND/OR uses the existing strong Kleene evaluator.

Every result retains rule truth, condition bounds/reasons, minimal supporting
conditions/artifact digests, checked witness references and independent coverage.
coverage_complete concerns that rule's conditions. coverage_health.complete concerns
all registered conditions in that window. Neither assesses general device health or
historical completeness. FALSE for one AND condition can coexist with missing
devices and DEGRADED coverage. Continuity gaps do not erase independent later facts.

The existing immutable contract supplies the demonstration correlation:
edge-device-02.cpu_usage >= 90 AND
edge-device-03.measurements.packets_per_second >= 8000 AND
edge-device-04.measurements.failed_logins >= 5.
Each EXISTS requires its own match within the same aligned gateway-ingress window,
not a simultaneous physical occurrence. COUNT_GE counts qualifying observations,
not the sum of a counter value. Thresholds remain synthetic demonstration settings.
The contract hash remains 5ac9d246d40fc6a333c68fe984025d7f6169bec2fe3e85589c5af3cee51204bd.

Legacy anomaly/correlation logic remains LEGACY_RECEIVED_PAYLOAD_BASELINE, identified
in Fog Analytics health metadata. New alerts/results use RCCD_SCOPED_RULES_V1 and
distinct COVERAGE_RULE_INCIDENT / COVERAGE_VISIBILITY types. Their output is not
merged into the legacy detector's claim of accuracy.

## Original Witnesses and Assurance

Optional canonical InputRecord disclosures are accepted through the Fog-local
repository method save_coverage_original_witness, not inferred from selected
transport UUIDs/sequences or aggregate means. Disclosed values/hash, device, epoch,
ingress sequence and window must match a signed RCC witness reference. Numeric
predicates are checked against the original values. Repeated disclosures are
idempotent; bounded collective checks detect contradictions with signed counts.
An authenticated contradictory disclosure quarantines its scope and reassesses
decisions. Unrelated or unauthenticated garbage cannot poison accepted evidence.

The witness and its RCC describe the same population: counts use max rather than
addition, so one input cannot manufacture two COUNT_GE matches. Witness storage is
bounded by 128 references / 8 MiB per checked scope and 65,536 bytes per record.

This is authenticated-summary assurance plus checks on disclosed originals, not
proof of every hidden input or physical-world truth. The exact microsecond position
of a partial disclosure is not proven by the RCC's input hash alone; v1 checks its
declared membership in the signed window. Full offline commitment recomputation
remains the separate N3 audit. Witness imports are optional local/offline audit
inputs; no free witness transport or new datagram schema is claimed. Live raw
telemetry is not automatically reclassified as original-ingress evidence.

## Durable Decisions and Alerts

Migration 004_n7_rules.sql additively extends the existing verdict table with stable
decision IDs, revisions and results, plus append-only coverage_rule_history.
It adds original witnesses, monitor cursors/gaps, alert intents, cooldowns, delivery
states/history and an authenticated-expiry lookup index. Existing rows are retained.

Deterministic UUIDv5 decision identity binds gateway/epoch/contract/window/rule;
alert identity additionally binds INCIDENT or VISIBILITY. Rule processing locks the
provisioned epoch before publication rows, matching N6's lock order. Decisions,
history, alert intents, cooldowns and publication completion commit atomically.
Exact reprocessing does not create new revisions when meaning/evidence is unchanged.

Late complete evidence can refine UNKNOWN to definite. N6 forks/retirement immediately
invalidate current truth, append revision history and revoke queued incidents.
Invalidation clears stale condition bounds/support pending N7 reassessment. N7 then
recomputes the affected window, preserving independent deciding conditions.

Alert Engine's opt-in POST /coverage-alerts accepts only alert_id and delivery
revision. Its transaction reads the authoritative persisted intent and current
decision, rejecting superseded requests. Alert insertion, delivery state/history
and receipt checkpoint commit together. A database failure returns 503, not a
durable receipt. Duplicate requests store no duplicate incident. Retraction preserves
the original alert row and records an inactive state rather than deleting history.

Decision status TRUE/FALSE/UNKNOWN is separate from INFO/WARNING/HIGH/CRITICAL.
TRUE incidents use locally provisioned synthetic severities. Visibility warnings
describe degraded/missing/expired/unsupported observation, not an invented attack.
Incident and visibility cooldowns are independently persisted. Cooldown uses
gateway window indices and committed intent creation, not ephemeral process clocks.
Late older windows may be suppressed when a newer incident was already admitted;
their verdict and suppression cause remain stored. Delivery failure does not waive
cooldown or guarantee eventual delivery.

## Monitor Lifecycle and Inspection

N7 is enabled only by the research override's COVERAGE_RULE_MONITOR_CONFIG and
COVERAGE_ALERTS_ENABLED=true. The base Compose/HTTP deployments remain unchanged.
Default evidence grace is 20 seconds; visibility cooldown is 30 ten-second windows.
Per-rule incident cooldown/severity is in config/rule_coverage_monitoring.json.
Policies must exactly match the provisioned rule set. Their resolved hash is pinned
in durable monitor state and cannot silently change on restart, including when
publications are pending.

The monitor starts at the last closed window, not an invented normal historical
trace. Deadline-only windows produce UNKNOWN/visibility when observations are
missing. Each tick processes at most six windows. A backlog exceeding 120 active
windows records FOG_MONITOR_DOWNTIME and resumes bounded monitoring, without
manufacturing normal skipped windows. Fog clock regression records a limitation
and does not reopen completed deadline windows. Gateway ingress time still defines
rule membership; Fog time only schedules visibility deadlines.

Crypto/database work runs off the async event loop. The existing receiver shutdown
drains uncancellable storage work. Alert delivery remains internal Fog HTTP and its
outcome never enters Edge reduction, reservation or scheduling.

Fog-local GET /research/rules?limit=20 returns current decisions; history=true returns
versioned records. Queries are limited to 1..100 and return 503 on unavailable
storage. /research/status identifies the active rule mode. The Streamlit coverage
view, active-alert filtering and other N8 visualization are not implemented here.
