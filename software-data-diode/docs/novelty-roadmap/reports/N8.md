## Implemented

### Fog Queries

Monitoring API coverage reads use only Fog PostgreSQL under a REPEATABLE READ,
READ ONLY transaction. Blocking work runs through asyncio.to_thread. The research
override mounts only the provisioned read-only contract into Monitoring API, not
the Edge ledger, private keys or the shared Edge audit volume. Research snapshot
queries do not invoke the legacy shared audit-file verifier. Baseline mounts and
audit behavior remain unchanged. Internal Fog health requests remain Fog-local.

Opt-in flags: COVERAGE_DASHBOARD_ENABLED for Monitoring API and
DASHBOARD_COVERAGE_ENABLED for Streamlit; both enabled by the coverage override.
The baseline API returns 404 for research queries and its UI omits the new view.
Readiness checks the needed N7 columns/tables when research viewing is enabled.

Endpoints:

| Endpoint suffix under /api/coverage | Read result and hard bounds |
|---|---|
| overview | Latest verdict statistics, unique completed capsule bytes, provisioned devices, freshness, signed forward state, contract and up to 32 outcome categories |
| verdicts | Stable descending (window_index, decision_id) keyset; limit 1-100, default 25 |
| decisions/{UUID} | Exact current verdict, supporting/missing references, up to 32 same-scope device capsules, truncation flag, two alert intents and 20 revisions |
| capsules/{64-hex-digest} | Exact signed artifact JSON, verification, scope quarantine/retirement, up to 96 part sizes, 128 disclosed-witness references and 32 conflict rows |
| capsules/{digest}/witnesses | Canonical originals as base64, sequence keyset, limit 1-16, default 8 |

Filters include gateway, ledger epoch, contract, device, rule, truth and inclusive
window-index range. Device filtering matches rule dependencies, not a generated
device-message count. Pagination order is immutable; later revisions remain visible.
Older pages keep their end-window bound while new first-page data can advance.
Queries are parameterized; invalid limits, identifiers, cursors and statuses fail
with 422. Missing records return 404, storage failures 503 without exposing SQL or
credentials. Connection and statement timeouts remain bounded. Totals can scan
historical rows within those timeouts; no unbounded result set is returned.

Migration 005_n8_queries.sql adds only indexes for keyset/filter queries, device
dependencies, receipt ordering and outcome categories. The existing research
migrator applied it successfully; all five indexes were checked in public.

### Dashboard Semantics

Evidence Coverage has device/rule/time/status filters, optional gateway/epoch/hash
filters, bounded previous/next pages and a persistent pinned rule-window inspector.
It shows definite yield and UNKNOWN rate, scoped reasons, condition bounds,
independent device coverage/freshness, contract hash, original-input witness
references, exact capsules, continuity and active/retracted/suppressed alert intent.
History and witness cursors allow further inspection without clearing selections.

TRUE means a supported matching rule result, FALSE a supported no-match result in
that rule's observation scope, UNKNOWN insufficient/limited/conflicting evidence.
FALSE is explicitly not globally safe or proof of complete device coverage. Rule
truth remains separate from alert severity. No sensor health is inferred from a
valid capsule. Same-window matches do not assert physical simultaneity.

Per-capsule original accepted counts, predicate-accounted counts, unresolved metric
counts, raw selection/reduction/drop/attempt accounting and quarantine are shown.
Conflicting variants are not summed into an original-observation total. Capsule
accounting is frozen at sealing; it does not prove later raw delivery.

Assurance is AUTHENTICATED_SUMMARY, with checked partial disclosures distinguished
from full OFFLINE_RAW_RECOMPUTATION. The dashboard does not independently recompute
hidden inputs and never claims an input digest proves their physical truth.

JSON/CSV page snapshots, decision records, capsule JSON and witness pages are
downloadable. CSV neutralizes leading spreadsheet formula characters. Downloads
use on_click="ignore". View responses are capped at 3 MiB; last-good caches have
one entry per resource, not a growing cache per window. Page navigation history is
bounded to 100 entries. Contracts bound selectable devices/rules to 16/32.

The existing dynamic st.fragment timer remains in use. Interval changes replace
the timer through the normal widget rerun. Pause removes the timer and stops data
requests for unchanged selections. Manual refresh increments a session nonce;
there is no unconditional st.rerun loop or sleep loop. Filter changes can fetch
new data even while paused. On timeout, only a matching-selection last-good record
is reused, with unchanged timestamps and a visible stale warning. Pinned inspection
survives refresh and page movement. Existing stale-element readability CSS remains.

The evidence view has its own scoped KPIs rather than the legacy 12-card row.
Legacy ingress counters are labeled Gateway inputs / Gateway accepted with their
process/epoch scope; historical Fog accepted totals are not divided into them.
Research active alert and critical-alert queries honor N7 intent retractions while
preserving stored alert history. Non-coverage legacy alerts remain included.

### Byte Accounting and Metrics

N4's byte service is not replaced. A small research-only accounting hook updates
durable RAW/EVIDENCE/STATE grant costs in the same existing grant transaction.
It includes signed headers/parts, fixed repeats and modeled network overhead.
Accounting starts explicitly at N8 activation, persists across restart and charges
uncertain grants once; it is not backfilled from incomplete historical logs. It
does not change scoring or consult Fog. State is validated and bounded, and the
new fields travel in the existing bounded signed STATE frames with their normal
budget. Existing signed capsules and replay identities are untouched.

Evidence fraction uses EVIDENCE / total from this one matched local-grant scope,
not confirmed receipt or physical wire measurement. The latest persisted signed
state's epoch/hash/gateway binding, timestamp, accounting start and pending
reservation/obligation counts are inspectable. These sender totals do not follow
the rule/time filters. Old state without matched counters reports Unavailable,
not zero. Fog historical unique completed-part payload bytes are a different
counter, excluding lost duplicates/repeats and network overhead.

Metrics refresh automatically from Fog persistence on /metrics, independent of a
dashboard visit. They are gauges, not process counters masquerading as history:

- coverage_metrics_available
- coverage_evidence_received_bytes
- coverage_evidence_forward_fraction
- coverage_pending_reserved_bytes
- coverage_pending_obligations
- coverage_sender_state_age_seconds
- coverage_rule_windows{truth=TRUE|FALSE|UNKNOWN}
- coverage_verification_failures

No window, digest, UUID, arbitrary reason or device is a metric label. Query failure
sets availability to zero and values to NaN rather than inventing zero failures.
Sender age accompanies possibly stale obligations/fraction. Failures count all
non-EVIDENCE_COMMITTED persisted outcomes, including conflict/expiry/assembly
failures, not distinct attacks. Existing System Health Grafana provisioning adds
Fog-datasource panels for these metrics. Optional collectors were not enabled.
