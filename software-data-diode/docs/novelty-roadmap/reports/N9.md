### Outcome Semantics

Each result records scenario, attack_type, expected_result, actual_result, passed,
detected, scope, timestamp, latency_seconds, queue_data, resource_data and reason.
Unmeasured latencies are null, not zero. detected is null/NOT_APPLICABLE for
failure/correctness cases and outside-scope demonstrations. UNKNOWN is a separate
truth value, not a detected attack or a no-event certificate.

The model campaign uses signed/reassembled production artifacts and the production
rule evaluator, but compares definite results with N1's independent full-ingress
oracle. The oracle receives canonical originals normalized independently of capsule
fact generation and InformationEngine methods. Missing evidence can remove a
definite result; valid redundant facts can retain it. No comparison treats a summary
mean as an original sample.

## Limits and Stop/Go

- AUTHENTICATED_SUMMARY is still a trusted gateway assertion. The test deliberately
  signs a consistent negative CPU summary while the hidden-input oracle is TRUE:
  Fog cannot cryptographically detect that lie. It is OUT_OF_SCOPE_TRUSTED_SIGNER,
  not a successful attack detection or an in-scope correctness counterexample.
- A generated match lost before durable admission can coexist with accepted-scope
  FALSE. The counterfactual generated oracle is TRUE, but this is outside the frozen
  accepted-gateway-ingress contract. No generated/physical completeness is promised.
- [PCAP](../evidence/N9/7b6a78fe56c9/campaign.pcap) records only IPv4 traffic to/from
  the pinned Fog-ingress address visible in the disposable diode namespace.
  Internal Fog HTTP is allowed. No-reply code, socket instrumentation and observed
  packets do not enforce physical unidirectionality. UDP and the shared host remain
  bidirectional; a privileged administrator can change routing, code and trust.
- Loss/failure semantics, clock jumps and process-crash boundaries include model
  or fault-injected executions. They are not all physical faults reproduced on the
  real Windows host. No general cryptographic proof, exhaustive distributed-system
  proof, sensor identity proof, side-channel audit or kernel security audit is claimed.
- No unlimited critical/evidence-delivery guarantee exists. Raw eviction, refusal,
  finite spool/assembly/storage bounds and stale UNKNOWN coverage remain legitimate.
  N4 signing-retention/retirement limits still restrict long-running campaigns.
- No browser redesign/check was required by N9; N8 UI tests remain in regression.
  No comparative graphs, paired confidence intervals or N10 performance claim is added.

**Assessment:** no wrong definite answer occurred in the tested trusted-ingress
traces. Proceed to carefully scoped N10 experiments, not to a claim of patentability,
hardware isolation or universal correctness. Before long runs, resolve the inherited
N4 documentation and reviewed retention/epoch procedure. Retain strong fixed-summary,
gap-aware FIFO, legacy and always-UNKNOWN comparisons; include evidence/repeat bytes,
admission refusals, UNKNOWN and receipt deadlines in matched budgets. N10 must use
repeated paired trials and may find no advantage. It has not been started here.
